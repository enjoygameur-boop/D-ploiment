PASSATION - RRTool / RobRun - fonctionnalite d aim SUIVANTE
==========================================================
Ecrite apres la livraison de "Ignore knocked". La fonctionnalite suivante
etant aussi une fonction d aim, elle reutilise directement une partie de ce
travail : meme section de menu, meme filtre, meme config, memes helpers,
meme procedure de deploiement. Lire ce document en entier avant d ecrire
une ligne.

----------------------------------------------------------
1. ETAT VALIDE EN JEU
----------------------------------------------------------
"Ignore knocked" fonctionne : option cochee, l aimbot ignore un joueur au
sol et continue de viser les debout. Rien d autre n a regresse.
Port de reference : 2239488 o, hash 7BF8F0F01B54855A.
Fichiers sources valides sauvegardes en *.OK_knock dans 2_src_port.
Sauvegarde complete zip a la racine (SAVE_FULL_knock_*).

2. CODE EN PLACE, A REUTILISER
----------------------------------------------------------
Toute fonctionnalite d aim suit le meme trajet. Les emplacements ci-dessous
sont ceux de la fonctionnalite knocked ; les numeros de ligne derivent,
chercher par motif.

- rr_game.h, pres de "dead" : champ d etat dans RR_PLAYER

- rr_game.c, snapshot_read, apres la reprise de hidden_in_object :
      if (cfg->aa_ignore_knocked) p->knocked = rr_char_is_knocked(snap[i].obj);
  Le calcul est conditionne par le reglage : option decochee = aucun cout,
  aucun changement de comportement. Conserver ce schema.
- rr_aim.c, ligne du filtre de cible : ajouter le champ au "continue".
      if (!p->addr || !p->valid || p->dead || p->knocked || ...) continue;
- rr_esp.c, hash de cache de rendu : MIX du nouveau champ, sinon l affichage
  se fige.
      MIX(p->dead); MIX(p->knocked); MIX(p->armor);
- rr_esp.c, bloc de defauts de config : written.<champ> = 1;
  et dans la condition de rechargement : loaded.<champ> == 1 &&
- menu_bridge.h, liste X(...) : X(nouveau_champ, 0, 0, 1)
- menu.html, section Targeting : label avec data-key="nouveau_champ".
  menu.html est compile dans l exe par app.rc a chaque build_port, rien a
  regenerer a la main.

Helpers de detection, rr_game.c, juste apres hidden_object_position :
cache de phases 8 emplacements + rr_knocked_by_static (croisement) +
rr_phase_verdict (verdict par nom d EnumItem, log une fois par instance) +
rr_char_is_knocked.

----------------------------------------------------------
3. FAITS VERIFIES SUR LA CHAINE ET LE RUNTIME
----------------------------------------------------------
- Character -> modele d etat : character + 0x1E0 (RR_OFF_CHAR_STATE),
  valider avec u_is(..., "BattleCharacterStateModel").
- Modele d etat -> modele knockout : + 0x30 (RR_OFF_CHAR_KNOCK_MODEL).
  L offset est SUR LE MODELE D ETAT, pas sur le character.
- Modele knockout -> conteneur de phase : + 0x18 (RR_OFF_KNOCK_PHASE).
- Conteneur : classe runtime "ReferenceData`1" (derive de
  NullablePrimitiveData<T> -> BasePrimitiveData<T>, champs _serializer 0x10
  puis _value 0x18). La valeur se lit donc a + 0x18 (RR_OFF_REF_VALUE).
- Valeur non nulle = instance "KnockoutPhaseDescription".
  Nom runtime de la phase de knockout : "knocked_out", EN MINUSCULES avec
  underscore. Un test sensible a la casse sur "Knock" ne matche pas.
- EnumItem : nom a + 0x10 (RR_OFF_DESC_NAME), Index a + 0x18
  (RR_OFF_ENUM_INDEX). Index de knocked_out observe : 0.
- Valeur nulle a + 0x18 = joueur debout, cas normal.
- La phase se lit SANS appel distant, uniquement par pointeurs.

----------------------------------------------------------
4. PROCEDURE DE BUILD ET DE DEPLOIEMENT
----------------------------------------------------------
1. build_port.bat par chemin absolu depuis 2_src_port. Zero erreur, exe
   horodate a l instant. Ne jamais continuer avec un binaire perime.
2. Purger 2_src_port\payload, le realimenter (kd2.exe, kernel-mode.sys,
   WebView2Loader.dll depuis 1_run\payload) et y copier le nouveau port.
   Comparer les SHA-256 : MATCH obligatoire.
3. build_aio.bat, TOUJOURS apres build_port.
4. Verifier que 1_run\RobRunPort.exe (que build_port recopie ligne 75) a le
   meme hash que la source. C est CE fichier que l AIO embarque, pas
   2_src_port\payload.
5. Installer l AIO dans 1_run et comparer les SHA-256 : MATCH obligatoire.
6. Tuer le jeu et l overlay avant de copier, puis supprimer les exe
   residuels de %LOCALAPPDATA%\Temp (> 2 Mo).
7. Redemarrage Windows UNIQUEMENT si le driver a change. Un port seul se
   teste par simple relance.

----------------------------------------------------------
5. VERIFICATIONS OBLIGATOIRES AVANT DE TESTER
----------------------------------------------------------
- L overlay extrait dans %LOCALAPPDATA%\Temp doit porter le hash du port
  fraichement compile. L overlay prend un nom de masquage variable
  (taskhostw, smartscreen, sihost, ctfmon, SearchProtocolHost...).
  Le controler par taille et par hash, jamais par nom.
- Un overlay de la session precedente encore vivant verrouille la
  destination : le lanceur echoue avec 0x20 et rejoue l ancien port.
  Toujours nettoyer avant de relancer.
- Le journal du port (dlog) s ecrit dans discovery.log, dans le repertoire
  courant de l overlay, donc %LOCALAPPDATA%\Temp. Si la copie de masquage
  echoue, il s ecrit dans 1_run\payload. Verifier les deux.
- Le log du lanceur (aio.log) ne contient que le demarrage, pas le dlog.

----------------------------------------------------------
6. POINTS OUVERTS
----------------------------------------------------------
- Le reglage ne survit pas toujours a un redemarrage : un "flag=0" a ete
  observe en cours de session alors que l option etait cochee. A traiter
  separement, ce n est pas un probleme d offset.
- p->dead n est JAMAIS assigne dans le chemin reel. Le filtre de cadavres
  n existe donc pas. La chaine correcte est connue : modele d etat + 0x10
  (_isDeadModel, IPrimitiveModel<bool>) -> + 0x10 (donnee BoolData) ->
  + 0x18 (valeur), cf. rr_esp.c vers la ligne 1560.
- RR_OFF_CHAR_ISDEAD vaut 0xF0 et ne sert a rien : la valeur juste est 0x10
  sur le modele d etat. Code mort.
- RR_OFF_KNOCK_FORWARD et RR_OFF_KNOCK_PHASE valent tous deux 0x18 ;
  RR_OFF_KNOCK_ENDTS et RR_OFF_KNOCKDOWN_ENDTS tous deux 0x10. Verifier le
  modele vise avant de les reutiliser.
- Le croisement par instance statique (rr_knocked_by_static) n est que
  journalise, jamais utilise pour le verdict. L offset du blob statique
  (RR_OFF_PHASE_KNOCKEDOUT 0x08) n est pas prouve.
- Le repli sur _endTs a ete retire : phase inconnue = pas au sol.

----------------------------------------------------------
7. ERREURS DEJA COMMISES, A NE PAS REFAIRE
----------------------------------------------------------
- Lire _isDeadModel (0x10 du modele) a 0xF0 : tout le monde devient mort,
  couleur 5, role/armure/arme masques, aimbot muet.
- Lire le modele knockout sur character + 0x30 au lieu du modele d etat.
- Traiter le conteneur ReferenceData`1 comme un booleen, ou sa valeur comme
  une instance de phase sans valider la classe.
- Tester le nom de phase en "Knock" alors que le runtime dit "knocked_out".
- Confondre down et mort : deux champs, deux filtres.
- En PowerShell 5.1, "if" n est pas une expression : ecrire $(if (...){}).
  Dans un motif de fin de ligne CRLF, [ \t]*$ ne matche pas : utiliser
  \r?$.
- Faire confiance a l horodatage : seuls les hash prouvent quelque chose.
